# AirIsland 设计与活动接入规范

本规范适用于所有功能、界面和 AI 辅助开发。目标是保持 AirIsland 轻量、及时、可预测。三层架构为强制约束，详见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 1. 设计来源与边界

参考 [Apple Live Activities](https://developer.apple.com/design/human-interface-guidelines/live-activities) 对有限时活动、简明信息和多种呈现形态的指导，适配 Mac 的交互方式。

以下三层职责、优先级、时长、设置分类是 **AirIsland 自身的产品规范**，不是 Apple 官方技术架构或 ActivityKit API 要求。不照搬 iPhone 的尺寸、手势和权限模型，不声称支持系统 ActivityKit 扩展。

## 2. 活动准入

接入前必须回答以下问题，答案写入改动说明：

1. 这是用户当前进行的哪件事？开始信号和真实数据源是什么？
2. 为什么此刻需要一眼看到？哪个字段是最重要的？
3. 怎样结束、取消、失败或过期？数据源失联时如何处理？
4. 收起时显示什么？强调时多显示什么？展开后有哪些必要操作？
5. 用户如何关闭这个活动？需要哪些权限？完整内容在哪里查看？

不能回答这些问题，就不应接入。功能有用不代表适合放进岛里。

允许的两类信息：有生命周期的进行中活动，以及用户明确操作后产生的短暂反馈。已移除文件暂存，不再接收拖入的文件、链接或文本。

## 3. 统一呈现

| 状态 | 展示内容 | 进入与退出 |
| --- | --- | --- |
| 空闲 | 自然收起，不显示虚构任务和填空文案 | 没有可见活动 |
| 收起 | 单一当前活动最重要的图形或状态 | 调度层选择 |
| 短暂强调 | 仍在岛内，补充本次变化的简短信息 | 真实事件触发，调度层自动收回 |
| 主动展开 | 当前音乐的必要控制 | 点击、悬停、手势或快捷键；离开后收起 |

短暂事件不能再生成岛下方的独立横幅，不能自行打开完整面板。已经展开时，系统反馈复用顶部状态区，不抢走当前音乐操作面板。本文中的“最小”是空闲/精简呈现原则，不承诺实现 iOS 多岛并列。

展开尺寸按音乐面板取值，窗口预留必要的阴影空间。物理刘海区域不可被文字和按钮占用。多显示器与无刘海屏幕必须可用。

## 4. 调度和生命周期

当前固定规则如下，只有调度层可以修改：

| 活动 | 优先级 | 保留时间 |
| --- | --- | --- |
| 用户调节音量、亮度、背光、麦克风状态 | 100 | 最近一次更新后 1.5 秒 |
| 电源状态变化 | 80 | 最近一次更新后 3 秒 |
| 切歌强调 | 60 | 最近一次更新后 3 秒 |
| 音乐播放状态 | 10 | 播放中；暂停后经过媒体闲置宽限期结束 |

- 一次只选出一个当前活动，所有屏幕观察同一调度结果。
- 同类更新合并；不同系统调节反馈互相替换。连续按键刷新值与截止时间，不堆积提示。
- 高优先级结束后恢复仍有效的活动。隐藏活动照常过期，不排队补播旧消息。
- 用户关闭一种活动时，清除它的可见状态和截止时间，不能只藏掉开关。
- 时间使用单调时钟；收起任务必须可取消，取消后不得继续执行过期回调。
- 本轮不增加活动轮播、优先级编辑器、第三方插件协议或 AI 任务占位。

## 5. 信息与动效

只提供任务相关信息与必要动作。品牌标识不替代真实封面，不在切歌时闪入应用大图标。新歌翻转一次，清晰度升级只原位更新；上一曲和下一曲保持相反方向。快速切换只保留最新目标，异步结果必须核对歌曲/任务标识。

动效服务于状态变化。支持系统“减少动态效果”，避免循环装饰、闪烁和反复吸引注意力。文字须可读，长内容裁剪或进入独立窗口，不靠缩小字号塞满。

岛的展开、收起、短暂强调、面板切换、手势回弹及内部交互共用 `IslandAnimations` 的弹簧曲线（响应 0.42、阻尼 1，无额外回弹），不按入口或方向另设时长。圆角、尺寸与封面位置必须连续同步变化，快速反向操作应从当前呈现状态接续，不能突变成直角或让封面越界。连续播放进度、频谱和文字滚动按真实内容更新，不作为交互过渡反复重启动画。

内容更新与动画作用范围分开：背景光晕的显隐动画只作用于透明度，不能覆盖背景尺寸或裁剪边界的动画；不得给整个内容子树无条件替换动画事务。背景颜色、封面清晰度和进度更新不得改变岛的几何过渡。验收必须检查过渡中间帧的实际轮廓和封面边界，不能只检查圆角参数或最终状态。

音乐封面在精简、速览和展开布局之间使用同一个持续存在的呈现实例，布局只提供透明占位。岛的高度、轮廓圆角与封面的位置、大小、圆角共用同一逐帧展开进度；仅设置相同曲线不足以保证同步，不能让它们各自启动过渡。布局与封面共用尺寸常量，不能在退场和入场内容中各绘制一份封面，也不能在封面位置动画之外叠加整个内容面板的缩放。文字区和刘海占位不绘制黑色矩形补丁；统一底色由岛的背景负责，避免过渡中遮挡封面。

音乐应用角标只作为封面的叠加层，不参与封面尺寸计算。角标的大小、偏移和透明度跟随同一展开进度，收起时保持附着在封面右下角，不能固定尺寸另做退场动画而向右下方漂移。

歌曲速览与精简播放状态之间，岛的宽度和文字应平滑过渡。动画由呈现层绑定呈现状态，不能依赖调度层的动画事务；封面清晰度或进度更新不应触发这段过渡。

顶部状态区全宽保持纯黑，封面光晕仅在下方淡入，不能勾出真实刘海或绘制假的刘海。顶部留黑高度依据当前窗口所在显示器的物理安全区，不能读取另一块首选显示器代替。收起时光晕平滑淡出，外轮廓保持连续过渡。

默认使用系统强调色与统一控件样式。播放器固定提供上一曲、播放/暂停、下一曲和进度拖动，复杂播放设置回到媒体应用。不要重新增加图标替换、Lottie 管理、每种事件单独的浮层位置、渐变、发光和动画编辑开关。

音乐统一使用系统“当前播放”，设置页和首次启动引导不再要求选择播放器来源。只展示系统提供的真实播放状态；来源不可用时不自动连接专用客户端，也不显示虚构播放内容。

## 6. 设置与权限

四个顶级分类依次为：通用、活动、显示与交互、关于。左侧菜单固定为 190 点宽，右侧内容区随窗口伸缩。通用页的退出按钮放在最后一组选项之后；关于页仅保留版本信息及其下方并排的 GitHub、下载最新版本按钮。页面操作按钮使用 macOS 原生样式和内边距，宽度随文字自适应、高度一致，靠右排列，随内容滚动，不设置底部固定栏。设置按用户意图组织，不按代码文件或内部三层命名。

活动设置只负责来源、开关和必要参数。统一外观与交互集中到显示与交互。调度规则由调度层维护，不开放任意组合。新增活动默认复用活动列表的子页面，不新增顶级侧栏项。

系统反馈不提供 Option（⌥）组合键的自定义动作；⌥ 加音量或亮度键由 macOS 处理。启用系统反馈替换后，普通调节和 ⌥⇧ 精细调节继续通过业务管理器提交活动，辅助功能权限仍按需申请。

权限按需申请：解释用途，允许拒绝，不为删除的功能保留权限页。岛默认不在锁屏展示，不主动展示敏感内容；用户可选择隐藏屏幕录制中的岛。不得擅自清除暂存文件和用户全部偏好。

## 7. AI 功能边界

未来获准接入 AI 后，岛只表达真实任务的运行、需要用户处理、完成或失败。关键确认必须由用户明确操作，详细对话、模型配置、工具执行记录和完整结果放到独立窗口。

没有真实任务时不放聊天输入框、不显示“AI 正在思考”假状态、不靠定时动画伪造进度，不为了“AI”标签增加功能。是否进入岛仍须通过第 2 节准入检查。

## 8. 验收

每项活动至少检查：空闲、开始、快速重复更新、被高优先级打断、恢复、结束/取消、失联、关闭开关，以及展开/收起两种上下文。涉及界面时另检查长中文、无刘海屏、全屏、多显示器、减少动态效果、权限拒绝。

必须区分模型测试、构建、界面渲染和真实应用操作。没有执行的项目应写明未验证，不得把构建成功写成“每次操作绝不会出错”。
